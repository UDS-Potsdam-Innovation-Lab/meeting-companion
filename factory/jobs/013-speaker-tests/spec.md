# Better tests for speaker recognition

## Problem
Job 004 shipped speaker detection: `SherpaDiarizer` gives one embedding per final segment, and `VoiceTracker`/`VoiceClusterer` cluster those embeddings online. Almost all of its tests use synthetic vectors and `ScriptedDiarizer`. The one real-model test is hand-run, needs two WAVs the person supplies, and only checks that two clean voices get two labels. Nobody can tell whether a change to the threshold, the short-segment rule or the model makes real meetings better or worse. The team needs a small, licence-clean multi-speaker corpus with reference labels, an accuracy measure, and a test that fails when accuracy regresses. Fast deterministic tests stay in the default suite.

## Scope
- in:
  - Corpus. A small multi-speaker test corpus under `src-tauri/testdata/speakers/`, built only from openly licensed recordings (see Open questions for the source):
    - Single-speaker source clips (16 kHz mono 16-bit WAV), committed.
    - A manifest with the source, speaker, utterance, licence and SHA-256 of every clip.
    - An `ATTRIBUTION.md`.
    - A scene file that describes each test meeting: which clips start when, overlaps, pauses, a noise level, and the reference text for each turn.
  - Scene builder (Rust, test-only). It mixes the clips of a scene in memory, deterministically, into one 16 kHz track and returns the reference speaker turns. Noise is generated by a seeded generator, not taken from a recording.
  - Scenes, de and en, 2–6 speakers. Together they cover:
    - a name round at check-in
    - overlapping speech
    - short turns (< 1 s)
    - a voice that comes back after a pause of at least 60 s
    - a speaker who says only a few words (≤ 2 s in total)
    - background noise
  - Accuracy measures (Rust, test-only):
    - diarization error rate (DER), with its parts: missed speech, false alarm and speaker confusion
    - a line-attribution accuracy per segment
    - optimal one-to-one mapping of hypothesis voices to reference speakers
  - A real-model accuracy test (`#[ignore]`, name contains `speaker_accuracy`). Each scene runs through the same segmenting the transcript pipeline uses (final segments of at most 3 s), then the real `SherpaDiarizer` and `VoiceTracker`, then the measures. It compares against committed per-scene thresholds and fails on regression.
  - Workflow scenarios on real diarizer output, through the existing `speakers` core functions:
    - name round
    - a voice assigned by hand and applied backwards
    - a "Who said this?" line override
  - CI. A script fetches one pinned speaker model and checks it against a committed SHA-256. CI caches the model by its checksum and runs the accuracy test with it. The hand-run command is documented in `AGENTS.md`.
- out:
  - Changes to product behaviour: `SAME_VOICE`, `MIN_SEGMENT_MS`, the clustering, the model preference and the UI stay as they are. If the baseline shows a better threshold, that change is a follow-up job.
  - Speech-to-text accuracy. Turn text comes from the scene's reference text, not from whisper.
  - Offline/whole-recording diarization, a new engine, or a model download inside the app.
  - UI tests with the real model. The "Who said this?" picker is covered at the core command (`choose_line`) the picker calls. Its UI is already covered by job 004's component and e2e tests with the fake.
  - macOS/Windows CI (deferred project-wide, decision 2026-10-30).
  - Voice profiles (job 010).

## Stack
Status: EXISTING
Rust core with `cargo test`, run by `npm test`. The real-model test is an `#[ignore]` test, as job 004 set up. The model fetch script follows `scripts/sherpa-onnx.mjs` (Node, pinned SHA-256). No new crate is needed. If the builder wants one for the optimal mapping, it uses a brute-force or Hungarian implementation in test code.

## Acceptance criteria
- [ ] AC1: The corpus is licence-clean and verifiable. Default suite, no model, no network.
  - A Rust test checks that every audio file under `src-tauri/testdata/speakers/` is listed in the manifest and that every manifest entry has a file.
  - Each file's SHA-256 matches the manifest.
  - Each licence is in the allowlist {`CC0-1.0`, `CC-BY-4.0`, `public-domain`}.
  - Every `CC-BY-4.0` entry has an attribution line in `ATTRIBUTION.md`.
  - The committed corpus stays under 15 MB in total.
  - A file that is unlisted, altered or carries another licence fails the test (temp-folder fixtures).
- [ ] AC2: Scenes are deterministic and cover the cases. Default suite. Building a scene twice gives bit-identical samples and identical reference turns. A test asserts these properties from the reference labels:
  - Both languages are present. Every scene has 2–6 speakers, and at least one scene has 6.
  - At least one scene has ≥ 10 % overlapped speech.
  - At least 5 turns are shorter than 1 s.
  - One speaker is silent for ≥ 60 s and then speaks again.
  - One speaker has ≤ 2 s of speech in total.
  - One scene has generated noise at an SNR of 10 dB (±0.5 dB, measured).
  - One scene is a name round: each speaker's first turn, within the first 2 min, carries an introduction that names an invited participant.
- [ ] AC3: The measures are correct and the gate fails on regression. Default suite, fakes only.
  - DER, missed speech, false alarm, speaker confusion and line accuracy match hand-computed values on small label fixtures. The fixtures include a permuted labelling (the optimal mapping gives 0 confusion), an extra hypothesis voice, unlabelled segments, overlap and a 0.25 s collar.
  - An oracle fake diarizer (embeddings from the reference speaker) runs through the real `VoiceTracker` on every scene. Its speaker confusion is 0 % outside overlaps and short segments.
  - A degraded fake (all embeddings identical, so one voice) makes the threshold check fail with a message that names the scene and the measure. This proves the gate would catch a regression.
- [ ] AC4: Real-model accuracy test with regression thresholds.
  - Command: `MEETING_COMPANION_SPEAKER_MODEL=<model.onnx> cargo test --manifest-path src-tauri/Cargo.toml -- --ignored speaker_accuracy`.
  - For each scene, the test runs the built track through the transcript windowing (final segments ≤ 3 s), `SherpaDiarizer` and `VoiceTracker`. It prints a table per scene: DER, missed speech, false alarm, confusion, line accuracy, voices found against speakers, and time per segment.
  - It fails when any scene exceeds its threshold in a committed thresholds file. The builder sets each threshold at the measured baseline plus a margin of at most 5 percentage points, and records the baseline and model next to it.
  - Scene-specific assertions:
    - The voice that returns after the pause gets the same label as before.
    - The few-words speaker is never given the label of another reference speaker. A missing or new label is allowed and reported.
    - In the noise scene, confusion is within its own threshold.
  - Without a model the test fails with a message naming the env var. It never downloads anything.
- [ ] AC5: Workflow scenarios on real diarizer output, in the same `#[ignore]` run. They use the existing core functions and the in-memory stores.
  - Name round: `name_round` on the name-round scene's labelled segments suggests, for each speaker, the participant that speaker introduced as. No suggestion points to the wrong person.
  - Applied backwards: after `choose_voice` assigns each voice to its mapped person at the end of a scene, line accuracy for earlier lines equals line accuracy for later lines. Every earlier line of an assigned voice shows that person.
  - "Who said this?": `choose_line` on one misattributed line (taken from the run) fixes exactly that line and changes no other line's speaker.
  - The `.transcript` bytes are identical before and after these choices.
- [ ] AC6: CI runs the heavy test with a checksum-pinned, cached model.
  - `node scripts/speaker-model.mjs fetch` downloads one pinned model (proposed: `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`, Apache-2.0, k2-fsa release "speaker-recongition-models"). It checks the model against `src-tauri/native/speaker-model.sha256` and fails on a mismatch. `verify <file>` exits 1 for a corrupted copy, and CI checks that, as for the sherpa archive.
  - `ci.yml` caches the model under a key from that checksum file. After `npm test`, CI runs the AC4 command with the debug test profile, so there is no second release build, and the step fails the job on regression.
  - The test code makes no network call. Only the script downloads, as the profile's builder rule requires.
  - `npm test` stays unchanged and needs no model. `AGENTS.md` documents the fetch and hand-run commands next to the existing `speaker` test.
- [ ] AC7: Nothing is kept or leaks.
  - The tests write audio only to in-memory buffers or to temp folders they remove.
  - No transcript or reference text, names or embeddings reach `crate::log!` output (log-capture assertion in the accuracy run).
  - Corpus, scene builder and measures are `#[cfg(test)]` or test-only. The release app binary does not include the corpus: CI checks that its size grows by < 100 KB against `main`, or checks for the absence of a corpus marker string.
  - No product source file outside `src-tauri/src/engines/` test modules, `scripts/`, `ci.yml`, `AGENTS.md` and `src-tauri/native/` changes behaviour. (NFR Privacy "Nothing leaves the device", NFR Maintainability "Tests for every acceptance criterion")

## Design
Source: none
Status: NOT NEEDED
No user-facing UI changes; tests, fixtures, a script and CI only.

## Surfaces
- User-facing UI: no.
- Security-relevant: yes. It adds a build-time download of model weights in CI, pinned by SHA-256, the same way as the sherpa-onnx archive. It also commits third-party voice recordings to the repo as test fixtures. Rules touched: NFR Privacy (nothing leaves the device: the tests make no network calls and no app runtime behaviour changes), NFR Architecture (the engine stays behind `Diarizer`). No secure-coding guideline is configured.
- Human gate: yes. The repo will hold recordings of real people's voices, and their licence and terms need a person's confirmation before they are committed. CI also gains a new downloaded binary artefact, the model weights. No product data, auth or permissions change.
- Audio/transcript data: yes, test fixtures only. Third-party single-speaker clips under an open licence are committed under `src-tauri/testdata/speakers/`. Mixed scenes, embeddings and labels exist in memory or in temp folders during a test run and are not kept. No user audio, and nothing changes in what the app records or stores.
- Leaves the device: no at app runtime. At CI time only, the pinned speaker model is fetched from GitHub Releases (k2-fsa) and checked against its SHA-256.
- Board (touch) layout: no.
- AI speaks or contributes unasked: no.

Size: normal

## Open questions
- Corpus source. This needs a human decision, and it is why the gate is set to yes.
  - Proposed: clips from Multilingual LibriSpeech (German) and LibriSpeech (English), both CC-BY-4.0 on openslr.org. The underlying LibriVox recordings are public domain.
  - Alternative: VoxPopuli (CC0, de and en). It is closer to spontaneous meeting speech.
  - Avoid Mozilla Common Voice: its terms forbid trying to determine speakers' identity, which conflicts with speaker-recognition tests even though the clips are CC0.
  - Synthetic TTS voices were considered and rejected as the main source. They are too clean and too alike to say much about real voices, and voice licences vary. Read audiobook speech is still cleaner than a meeting room, so the thresholds measure regressions, not absolute real-world quality.
- Name round without speech-to-text: the introductions ("Ich bin Mara Klein") are reference text attached to the speaker's first turn, not spoken names in the audio. The test checks that diarization feeds the name round correctly, not whisper's recognition of names. Real spoken introductions would need TTS or own recordings. Both are possible as a follow-up.
- Segmentation: the accuracy run cuts the reference turns into windows of at most 3 s, following the transcript pipeline's rule, instead of running whisper. If the builder can drive the real `Transcriber` windowing with `ScriptedSpeechToText` without a model, that is preferred.
- Profile rule "criteria are testable without models": every criterion has a deterministic part in the default suite (AC1–AC3, the fakes in AC3). The real-model parts (AC4, AC5) are `#[ignore]` tests that CI feeds with a pre-fetched model, as the feature asks.
- Thresholds are calibrated on the first run with the pinned model. A different model, for example the one the scan prefers on a dev machine, may need its own thresholds. The test reads the thresholds for the pinned model's file name and only prints, without failing, for an unknown model.
- CI time and disk: the model is about 27 MB, and the run is expected to take under 2 min on `ubuntu-latest` in the debug profile. If the runner's disk gets tight again, the step moves to its own job.
- Split, if needed: (a) AC1–AC3 (corpus, scenes, measures, gate with fakes; no model, no CI change) and (b) AC4–AC7 (real-model run, workflow scenarios, CI model fetch).
